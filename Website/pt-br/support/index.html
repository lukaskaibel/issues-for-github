Perguntas frequentes

Preciso de uma conta do GitHub?

Para trabalhar com as suas próprias issues, sim. Para conhecer o app antes, toque em Explorar com dados de exemplo na primeira tela: dois projetos de exemplo, guardados no seu dispositivo, em que todos os recursos funcionam.

Como inicio sessão?

Com Iniciar sessão com o GitHub ou com um token de acesso pessoal (classic) que tenha os escopos repo, project e read:org. Depois de iniciar sessão em um dos seus dispositivos, os outros iniciam sessão sozinhos pelas Chaves do iCloud.

Por que não vejo minhas issues?

Os quadros mostram as issues que estão em um GitHub Project, com o campo Status do projeto como colunas. Os repositórios que seus projetos usam também ficam na barra lateral, com todas as issues deles: as que não estão em nenhum dos seus quadros aparecem em Sem projeto, e um clique as coloca em um quadro. Minhas issues mostra todas as issues abertas atribuídas a você, estejam em um quadro ou não.

Faltam os projetos de uma organização.

Algumas organizações só permitem apps aprovados pelos proprietários. Peça a um proprietário que aprove o Issues ou inicie sessão com um token de acesso pessoal que tenha acesso à organização.

Funciona offline?

Sim. Toda alteração aparece na hora e aguarda no dispositivo até haver conexão; depois vai para o GitHub. Se outra pessoa alterou o mesmo texto nesse meio-tempo, as edições são combinadas e, onde elas se sobrepõem, você escolhe qual manter.

O que aparece na Entrada?

Suas notificações do GitHub sobre issues e pull requests: quando alguém atribui algo a você, menciona você ou a sua equipe, comenta em uma issue que você acompanha, pede sua revisão ou fecha, reabre ou faz o merge de uma. Releases, execuções de CI e discussões ficam no GitHub. O que você lê ou arquiva na Entrada também fica lido ou concluído em github.com. O GitHub não notifica sobre cartões movidos nem reações, então a Entrada também não. As suas issues com prazo também aparecem lá, no dia e mais uma vez na manhã seguinte, se ainda estiverem abertas.

A Entrada diz que meu token não pode ler notificações.

O GitHub não permite que tokens fine-grained leiam notificações. Inicie sessão com o GitHub ou use um token de acesso pessoal (classic) com o escopo repo; todo o resto funciona das duas formas.

Que notificações o app envia?

Lembretes de issues com prazo: no dia em que vence o prazo de uma issue atribuída a você e mais uma vez na manhã seguinte, se ela ainda estiver aberta. Cada um dos seus dispositivos os agenda sozinho a partir dos prazos, para que cheguem na hora; defina o horário ou desative-os nos Ajustes. Outras novidades do GitHub, como comentários e menções, aparecem na Entrada sempre que você abre o app, mas não chegam como notificação: o GitHub só consegue enviá-las a um app por meio de um servidor próprio do app, e o Issues propositalmente não tem nenhum.

Um prazo pode ter horário?

Não. O prazo é o campo “Due date” do projeto no GitHub, e as datas do GitHub são dias sem horário. O lembrete chega no horário definido nos Ajustes, 9:00 por padrão.

Em quais idiomas ele está disponível?

Inglês, alemão, francês, espanhol, português (Brasil), russo, japonês, coreano e chinês (simplificado). Ele segue o idioma do seu dispositivo. Para usar outro só no Issues, escolha-o no iPhone e no iPad em Ajustes › Apps › Issues › Idioma e, no Mac, em Ajustes do Sistema › Geral › Idioma e Região › Aplicativos. O que vem do GitHub, como títulos, colunas e etiquetas, continua como a sua equipe escreveu.

Como removo meus dados?

Encerrar sessão remove do dispositivo a cópia dos seus projetos, issues e notificações; Encerrar todas as sessões também remove o login das Chaves do iCloud. Apagar o app remove tudo o que ele guardou. Mais detalhes na política de privacidade.

Custa alguma coisa?

Não. O Issues é gratuito e de código aberto; o código está no GitHub.
