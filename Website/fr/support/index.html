Assistance

Une question, un problème ou une idée ? Écrivez un e-mail ou ouvrez un ticket sur GitHub. Chaque message est lu.

E-mail issues.app@icloud.com GitHub Issues Bugs et demandes de fonctionnalités, en public. Sécurité Signaler une vulnérabilité en privé.

Questions fréquentes

Ai-je besoin d’un compte GitHub ?

Pour travailler avec vos propres tickets, oui. Pour découvrir l’app d’abord, touchez Explorer avec des données d’exemple sur le premier écran : deux projets d’exemple, enregistrés sur votre appareil, où toutes les fonctionnalités marchent.

Comment me connecter ?

Avec Se connecter avec GitHub, ou avec un jeton d’accès personnel classique doté des scopes repo, project et read:org. Dès que vous êtes connecté sur l’un de vos appareils, les autres se connectent d’eux-mêmes grâce au trousseau iCloud.

Pourquoi ne vois-je pas mes tickets ?

Les tableaux affichent les tickets d’un GitHub Project, avec le champ Status du projet comme colonnes. Les dépôts qu’utilisent vos projets figurent aussi dans la barre latérale, avec tous leurs tickets : ceux qui ne sont sur aucun de vos tableaux sont regroupés sous Aucun projet, et un clic les place sur un tableau. Mes tickets affiche tous les tickets ouverts qui vous sont assignés, sur un tableau ou non.

Il manque les projets d’une organisation.

Certaines organisations n’autorisent que les apps approuvées par leurs propriétaires. Demandez à un propriétaire d’approuver Issues, ou connectez-vous avec un jeton d’accès personnel qui a accès à l’organisation.

L’app fonctionne-t-elle hors ligne ?

Oui. Chaque modification s’affiche aussitôt et attend sur l’appareil qu’une connexion soit disponible, puis part vers GitHub. Si quelqu’un d’autre a modifié le même texte entre-temps, les modifications sont fusionnées, et là où elles se chevauchent, vous choisissez laquelle garder.

Qu’est-ce qui apparaît dans Réception ?

Vos notifications GitHub concernant les tickets et les pull requests : quand quelqu’un vous assigne un ticket, vous mentionne ou mentionne votre équipe, commente un ticket que vous suivez, vous demande une revue, ou ferme, rouvre ou fusionne un ticket ou une pull request. Les releases, les exécutions de CI et les discussions restent sur GitHub. Ce que vous lisez ou archivez dans Réception est aussi lu ou terminé sur github.com. GitHub n’envoie pas de notification pour les cartes déplacées ni pour les réactions ; Réception non plus. Vos tickets arrivés à échéance y apparaissent aussi, le jour même et une fois encore le lendemain matin s’ils sont toujours ouverts. Il en va de même des tickets que votre propre compte vous a assignés en dehors de l’app, avec gh, un script ou un agent de code connecté avec votre compte : GitHub ne vous notifie pas de ce que fait votre propre compte, alors l’app les cherche elle-même. Ce que vous vous assignez dans l’app n’y apparaît pas.

Réception indique que mon jeton ne peut pas lire les notifications.

GitHub ne permet pas aux jetons à granularité fine (fine-grained) de lire les notifications. Connectez-vous avec GitHub, ou utilisez un jeton d’accès personnel classique avec le scope repo ; tout le reste fonctionne dans les deux cas.

Quelles notifications l’app envoie-t-elle ?

Des rappels pour les tickets arrivés à échéance : le jour où un ticket qui vous est assigné arrive à échéance, et une fois encore le lendemain matin s’il est toujours ouvert. Chacun de vos appareils les planifie lui-même à partir des échéances, ils arrivent donc à l’heure ; réglez l’heure ou désactivez-les dans les réglages. Les autres nouveautés de GitHub, comme les commentaires et les mentions, apparaissent dans Réception chaque fois que vous ouvrez l’app, mais pas sous forme de notification : GitHub ne peut les envoyer à une app que par un serveur propre à celle-ci, et Issues n’en a délibérément aucun.

Une échéance peut-elle avoir une heure ?

Non. Une échéance correspond au champ « Due date » du projet sur GitHub, et les dates de GitHub sont des jours sans heure. Le rappel arrive à l’heure définie dans les réglages (9:00 par défaut).

Quelles langues l’app parle-t-elle ?

Anglais, allemand, français, espagnol, portugais (Brésil), russe, japonais, coréen et chinois (simplifié). Elle suit la langue de votre appareil. Pour en utiliser une autre pour Issues seulement, choisissez-la sur iPhone et iPad dans Réglages › Apps › Issues › Langue, et sur Mac dans Réglages Système › Général › Langue et région › Applications. Ce qui vient de GitHub, comme les titres, les colonnes et les étiquettes, reste tel que votre équipe l’a écrit.

Comment supprimer mes données ?

Se déconnecter supprime de l’appareil la copie de vos projets, tickets et notifications ; Se déconnecter partout supprime aussi vos identifiants du trousseau iCloud. Supprimer l’app efface tout ce qu’elle a enregistré. Pour en savoir plus, consultez la politique de confidentialité.

Est-ce payant ?

Non. Issues est gratuit et open source ; le code est sur GitHub.
